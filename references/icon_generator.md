# 幾何学アバター生成ツール システム仕様書・設計書

## 1. システム概要
* **システム名:** プログラマブル幾何学アバター生成サービス（Identicon Generator）
* **目的:** 入力文字列（シード値）を元に、決定論的かつ一意な左右対称の幾何学アイコン（Identicon風）を動的に生成・配信する。
* **基本方針:**
  * 外部有料APIサービスに依存しない完全無料でのサーバーレス運用
  * 12-Factor App / ステートレス設計に準拠し、Google Cloud Runへ即時スケールアウト可能な構成

---

## 2. システム構成・アーキテクチャ

### 2.1 アーキテクチャ図
```text
[ クライアント (ブラウザ) ]
        │
        ▼ (HTTPS / 8080)
[ Google Cloud Run ]
  └─ [ Go Web サーバーコンテナ (Distroless) ]
        ├─ GET /           : 静的フロントエンド (HTML/CSS/JS)
        └─ GET /api/avatar : 動的PNG画像生成エンジン
```

### 2.2 技術スタック
* **言語:** Go（標準ライブラリ `image`, `crypto/md5`, `net/http`, `embed` のみ）
* **フロントエンド:** HTML5, Tailwind CSS (CDN), Vanilla JS
* **コンテナ基盤:** Docker（Multi-stage build, ベース: `gcr.io/distroless/static-debian12`）
* **デプロイ先環境:** Google Cloud Run（Artifact Registry 経由）

---

## 3. 機能要件・仕様

### 3.1 エンドポイント仕様

#### ① フロントエンド配信
* **パス:** `GET /`
* **機能:** 入力フォーム・プレビュー領域・ダウンロード機能を持つSPA画面を返却。
* **実装方式:** Go 1.16+ の `embed` パッケージにより、単一バイナリ内にHTMLを静的同梱。

#### ② アバター画像生成 API
* **パス:** `GET /api/avatar`
* **クエリパラメータ:**
  * `seed` (string, 任意): アイコン生成の元となる文字列。未指定時は `default` を適用。
* **レスポンス:**
  * **Content-Type:** `image/png`
  * **HTTPステータス:** `200 OK`
  * **画像サイズ:** 250px × 250px（正方形）

## 4. 詳細設計（画像生成ロジック）

### 4.1 アルゴリズム概要
入力文字列からMD5ハッシュ（16バイト）を算出し、色情報と5×5マトリクスの描画パターンを一意に決定する。

```text
[ 入力文字列 (seed) ] 
       │
       ▼ MD5 ハッシュ化 (16バイト配列)
 ┌─────┴───────────────────────────────┐
 │ [Byte 0..2] : メインカラー (RGB)    │
 │ [Byte 3..15]: 5×5グリッドの塗潰し判定 │
 └─────────────────────────────────────┘
       │
       ▼
 [ 5×5 グリッド生成（左右対称ミラーリング） ]
       │
       ▼ (1セル = 50px × 50px 展開)
 [ 250px × 250px PNG 画像出力 ]
```

### 4.2 各種パラメータ設計
1. **カラーパレット決定:**
   * **メインカラー:** ハッシュ配列の `hash[0] (R)`, `hash[1] (G)`, `hash[2] (B)` を抽出。
   * **背景色:** 固定のライトグレー（`RGBA{240, 242, 245, 255}`）。
2. **マトリクスパターン生成:**
   * 5×5 のグリッドを作成（計25セル）。
   * 左右対称性を担保するため、左側3列（列0、列1、列2）のみハッシュ値の偶数/奇数判定で塗りつぶし（`true/false`）を決定。
   * 列3は列1、列4は列0の値をコピーして反転配置（ミラーリング）。
3. **ラスタライズ（描画）:**
   * 1セルあたり 50px × 50px で描画し、合計 250px × 250px の `image.RGBA` を構築。
   * `image/png` エンコーダーによりストリーム出力。

## 5. インフラ・コンテナ設計

### 5.1 コンテナ設計仕様
* **マルチステージビルド:**
  * **Build Stage:** `golang:alpine` で静的リンクバイナリ（`CGO_ENABLED=0`、`-ldflags="-s -w"`）を生成。
  * **Runtime Stage:** `gcr.io/distroless/static` を採用し、シェルやパッケージマネージャーを排除した超軽量・高セキュリティな最小イメージを構築。
* **実行ユーザー:** `nonroot`（UID/GID: 65532）で実行し、root特権を排除。
* **ポート設定:** 環境変数 `PORT` を参照（未指定時は `8080` をフォールバック）。

### 5.2 クラウド環境（Google Cloud Run）設計
* **インスタンス設定:**
  * **最小インスタンス数 (min-instances):** `0`（完全従量課金・コールドスタート許容）
  * **最大インスタンス数 (max-instances):** `5`（想定外のスパイクや課金防止のセーフティガード）
  * **メモリ / CPU:** `128MiB` / `0.5 vCPU`（十分なスペック）
  * **Ingress:** すべてのトラフィックを許可（パブリック公開）
  * **認証:** 未認証の呼び出しを許可

---

## 6. 非機能要件・セキュリティ方針

* **ステートレス性:** サーバー側でのファイル保存（ストレージ書き込み）やDB接続は一切行わず、リクエストごとにオンザフライで生成。
* **セキュリティ:**
  * 外部入力（`seed`）はMD5ハッシュ計算のみに利用し、OSコマンド実行やSQLインジェクションのリスクを根本から排除。
  * 最小権限コンテナ（Distroless nonroot）によるホスト保護。
* **パフォーマンス:**
  * 単一バイナリ・軽量コンテナのため、コールドスタート速度は数百ミリ秒以内。
  * レスポンスサイズは約1〜2KBのPNG画像となり、ネットワーク負荷を最小化。

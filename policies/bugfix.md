# バグ修正ポリシー (Bug Fix Policy)

本ドキュメントは、不具合・障害修正における優先順位および作業プロセスを定義します。

## 1. 修正優先順位・プロセス (Fixing Process)
1. **再現テストの先行作成 (Red Test First)**:
   - 修正コードを書く前に、まずバグが再現して失敗する自動テストコード（Red Test）を優先作成すること。
2. **最小限のコード修正 (Minimal Impact)**:
   - バグの根本原因に対して最小限の範囲でコードを修正し、無関係なリファクタリングやコード整形を同時に行わないこと。
3. **退行テストの通過確認 (Regression Check)**:
   - 再現テストおよび既存の全テストが通過（Green）することを確認すること。

## 2. 症状隠蔽の禁止 (Root Cause Principle)
- エラーの発生箇所を単に `try-catch` や `if err != nil` で握り潰す「症状パッチ」を固く禁止する。
- 必ず上流のデータ生成・呼び出し元まで追跡し、契約（Contract）が壊れている根本原因を修正すること。
